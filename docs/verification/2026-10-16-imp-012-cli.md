## 🎓 Explicação para a equipe

A ferramenta do computador já sabe qual projeto usar. É como colocar o endereço correto no envelope antes de enviar uma alteração.

Entrada: comando com a referência do projeto → processamento: a ferramenta usa a autorização do administrador e confere o projeto no Supabase → saída: vínculo local em `supabase/.temp/project-ref`. Esse vínculo fica neste computador; não cria tabelas nem substitui o login dos usuários A/B do app.

Uma migration é uma receita de alteração do banco, escrita em SQL e guardada no Git. O banco remoto é a planilha compartilhada na nuvem; o arquivo local é a receita no computador. Guardar a receita permite revisar e repetir a mesma mudança, em vez de depender da memória dos cliques no painel.

Fluxo preparado para a task de tabelas: criar a migration → revisar SQL → conferir o projeto vinculado → simular com `db push --dry-run` → aplicar somente as mudanças revisadas. Essa aplicação ainda não aconteceu.

Pode falhar se a autorização expirar, a conexão cair ou o projeto vinculado estiver errado. Por isso o agente confere a referência antes de aplicar alterações. Senhas/tokens ficam nas ferramentas privadas do responsável; não entram em Git, Notion ou chat.
